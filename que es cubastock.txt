1. IDENTIDAD DEL PROYECTO
Nombre: CubaStock 2.0

Descripción: Aplicación web mobile-first de gestión de inventario y ventas para pequeños negocios en Cuba (cafeterías, tiendas, etc.).

Principio fundamental: Offline-first. Si hay Internet, sincroniza. Si no hay Internet, sigue trabajando. Las ventas se guardan en IndexedDB local y se sincronizan automáticamente al recuperar la conexión.

Público objetivo: Dueños de pequeños negocios y sus dependientes (empleados).

2. STACK TECNOLÓGICO
Capa	Tecnología
Frontend	React 19 + Vite
Backend	Node.js + Express
Base de datos	PostgreSQL (servidor) + IndexedDB (cliente)
Autenticación	JWT (almacenado en localStorage)
Estilos	CSS puro con variables (dark theme)
Notificaciones	Notificaciones locales del navegador (stock bajo, stock crítico, producto agotado, vencimiento próximo) + alertas Telegram al grupo del negocio
Gráficos	Recharts (para reportes)
PWA	Service Worker (sw.js) para modo offline y caché

4. ROLES Y PERMISOS
Rol	Permisos
ADMIN	Todo: crear/editar/eliminar productos, modificar stock, ver todos los reportes, gestionar dependientes (crear, editar, eliminar, resetear contraseña, asignar turnos), ver historial, ver estadísticas, recibir notificaciones de stock bajo/vencimiento.
DEPENDIENTE	Solo registrar ventas, consultar inventario (sin modificar), ver su propio panel con resumen de ventas, ver comparativa día/anterior, recibir notificaciones (si el admin las activa).

✅ Panel ADMIN con 6 botones: Ventas, Inventario, Reportes, Historial, Dependientes, Estadísticas.

Dos canales: notificación local del navegador mientras la app está abierta y mensajes Telegram idempotentes al grupo configurado en el backend. No hay Web Push.

✅ Fondo animado con partículas, estrellas, grid, nebulosa, líneas de escaneo.

✅ Diseño oscuro con variables CSS (glassmorphism, transiciones suaves).

7. REGLAS ESTRICTAS PARA EL ASISTENTE DE IA
Regla	Explicación
No cambiar la arquitectura sin autorización	No modificar la estructura de carpetas, ni el flujo offline-first, ni la lógica de negocio fundamental.
No eliminar funcionalidades existentes	Todo lo que ya funciona debe mantenerse (ventas, inventario, dependientes, reportes, offline).
No introducir dependencias innecesarias	Si una nueva funcionalidad requiere una librería externa, primero preguntar.
Mantener offline-first	Cualquier nueva funcionalidad debe funcionar sin conexión a Internet (guardar en IndexedDB y sincronizar después).
Usar las variables CSS para estilos	No usar colores fijos; usar var(--text-primary), var(--accent), etc.
No cambiar el comportamiento de la autenticación	JWT en localStorage, expiración a las 8h, roles ADMIN/DEPENDIENTE.
Código completo para reemplazar	Cuando se proporcione un archivo modificado, debe ser el archivo completo (no solo fragmentos) para que el usuario pueda reemplazarlo directamente.
Explicar los cambios	Cada entrega debe incluir un resumen claro de qué se cambió, por qué y cómo afecta al sistema.
No tocar el fondo animado (App.css)	Las animaciones del fondo (partículas, estrellas, grid, etc.) son parte de la identidad visual; no modificarlas sin consultar.
Respetar el diseño dark theme	No introducir elementos con colores claros que rompan la coherencia visual.
No sobrecargar el frontend	Evitar renderizados innecesarios, usar useMemo, useCallback cuando sea necesario para mantener el rendimiento.
Seguridad en el backend	Todas las rutas deben tener los middlewares authenticateToken, requireAdmin o requireStaff según corresponda. No exponer información sensible.
